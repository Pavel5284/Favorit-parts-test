# Подбор автозапчастей (React + Redux Toolkit, JavaScript)

Двухэтапный поиск через API «Проценка» (Фаворит Моторс): артикул → производители → предложения и аналоги.

## Запуск
```bash
npm install
cp .env.example .env   # впишите свой ключ покупателя в VITE_API_KEY
npm run dev            # http://localhost:5173
npm test
npm run build
```
**Нужен рабочий ключ покупателя.** Ключ `0000…0001` из документации — заглушка из примеров. После изменения `.env` перезапустите `npm run dev`.

## Что внутри
- **Этап 1.** Поле артикула; поиск запускается через 600 мс после последнего символа (от 2 символов) или по Enter. Результат — список уникальных производителей.
- **Этап 2.** Клик по производителю → запрос с `number`, `brand`, `analogues=on`. Таблица: название / производитель, цена, остаток. Метки «Искомая деталь» / «Аналог», фильтр «Только в наличии», раскрывающийся список складов (цена, остаток, срок отгрузки).
- **Цена** берётся со складов (минимальная среди тех, где есть остаток): поле `price` верхнего уровня API использовать не рекомендует.
- **Состояния.** `idle / loading / succeeded / failed` для каждого этапа; лоадер, пустая выдача, ошибки сервиса (в т.ч. с кодом 403), сбой сети, кнопка «Повторить».
- **Устойчивость.** Ненужные запросы отменяются (`AbortController`), запоздавшие ответы не портят состояние, `ErrorBoundary` (классовый компонент) ловит падения рендера.
- **Верстка.** Bootstrap 5 + CSS Modules рядом с компонентами: Bootstrap отвечает за готовые компоненты и тему, модули — за раскладку и собственные стили. Grid для раскладки, Flexbox для шапки и поиска, на телефоне таблица превращается в карточки. Шрифт Inter (с кириллицей), иконки Bootstrap Icons.

## Структура
```
src/api/partsApi.js        запросы, ошибки, нормализация ответа
src/store/partsSlice.js    Redux-состояние обоих этапов
src/components/<Name>/    Component.jsx и Component.module.css в отдельной папке
src/utils/format.js        форматирование цены и даты отгрузки
src/index.css              глобально только токены и фон страницы
src/**/*.module.css        стили компонентов (у каждого компонента свой модуль)
```

## Тесты (`npm test`)
Проверяют то, что легко сломать, а не «закрывают строки»: выбор цены, пустой ответ API («не найдено»), ошибки (в т.ч. 403 и отмена запроса), игнорирование устаревших ответов в Redux, debounce, сквозной сценарий «артикул → бренд → таблица», повтор после сбоя, ErrorBoundary.

## Важно
API отдаётся по `http` и без CORS, поэтому запросы идут через прокси `/api`: адрес и путь задаются в `.env` (`API_PROXY_TARGET`, `API_PROXY_PATH`), см. `vite.config.js`.
Для продакшена нужен такой же прокси на сервере (nginx и т.п.), а ключ лучше хранить на бэкенде.
